# Sutros private checkups and evidence review

The user requests a more useful wekup window, reports that distinguish measured facts from uncertain claims, and a community that only publishes checkups when their owners ask for help. They explicitly requested division of work with the original Claude Fable 5.1 chat and have authorized continued live deployment in this task.

## Interface

- The existing wekup dialog gains a translucent background toggle, bounded dragging and resizing, and keyboard controls. Text remains readable. It stays reachable on phones and short landscape screens. Existing account isolation, focus handling, glossary, and draft protections remain.
- Narrow the launcher, retaining an accessible label. Preserve identical SVG arrows on all devices.
- Replace the checkup's spinner-only treatment with stage progress. Never report 100 percent before receiving the finished report. Reset original icons for every new checkup. Security uses a lock. Busy chat text says Thinking.
- Center definition and feedback progress copy. Remove recent public checkups; retain the community.

## Private reports and voluntary public help

New and historical reports are readable only by owner/admin unless an active bulletin post explicitly publishes that report. Existing active bulletin posts preserve their prior opt-in. Ownerless old reports cannot be claimed. Do not change saved report observations or signatures to implement access control.

Apply access control to report JSON, lists, host lookup, screenshot artifacts, badges, signature verification, feedback, reassessment, recheck and private conversation routes. Host cooldown must not disclose another owner's private report ID. Report history requires an account and shows its own reports. Public community listing remains available.

Owners can remove their own bulletin posts and helper listings from their account. Removal withdraws public report access while preserving their private checkup. Require verified accounts to create helper listings. Existing ownerless listings remain stored but are not published as verified account listings. Use soft deletion so creation limits remain meaningful.

Email contact uses the verified account address rather than claiming DNS or an AI can establish mailbox ownership. HTTP(S) contact and the report website must be reachable via the existing SSRF-safe network layer before public posting. Clearly distinguish reachable website, verified contact, and business legitimacy.

## Evidence and grading

Give loading shells up to 7000 ms to become usable, within the overall operation budget. Ready pages need no fixed delay. Persist actual elapsed readiness time separately from load-event timing. Blocked, timed-out and unreadable pages cannot establish blank/broken layout findings.

After writing the draft and attaching proof, run a bounded final evidence review before scoring, signing, saving and delivering. It may annotate or withhold unsupported claims from grading. It must not invent evidence, new findings, more severe findings or broken interactions. Review failure remains explicit; an AI review does not guarantee correctness.

Award A+ for no actionable issues, excluding minor notes, only when adequate coverage and final review are complete. Unresolved non-minor agent observations prevent A+ while remaining excluded from numeric penalties. Incomplete scans remain unrated. Badge color and ring proportion match the actual grade and score.

Runtime errors retain page/frame URLs, bounded full message and stack, and one-based file/line/column. Show the exact recorded bundle location. Do not invent original source maps, HTML lines, DOM elements, or a failing button. Explain when a visual/HTML location cannot be established. React hydration recovery errors are not proof of broken controls.

## Sexual-image screening

Screen captured public page images before the full scan. Only sexual NSFW imagery causes a content denial. Violence in news, ordinary news discussion, and educational/medical context alone must not cause a denial. Page text is untrusted evidence, never instructions to the classifier.

Reuse bounded public-address-pinned browser requests. Capture a bounded sample of rendered imagery and send image bytes, not arbitrary target URLs, to moderation. A positive sexual-image result receives a context review to avoid confusing editorial/educational content with pornography. Never save rejected screenshots or send them to the frontend. Unknown/unavailable classification must not be called a content violation or a confirmed safe website. Report the sampling limit honestly.
